01What AGENTS.md is for

`AGENTS.md` 是项目里的 agent 使用说明

可以把它理解成给 Codex 看的项目说明书。它不替代 README，也不替代 CI 配置；它负责告诉 agent 在这个仓库里如何工作、如何验证、哪些事情必须先确认。

Scope

作用范围

根目录文件通常覆盖整个仓库。子目录里的 `AGENTS.md` 可以补充该目录的局部约定，更深层说明对更具体的文件生效。

Priority

优先级

用户当次消息优先于仓库说明。系统和开发者指令仍然更高层。`AGENTS.md` 适合表达项目规则，不适合绕过安全边界。

Content

写什么

写构建命令、测试命令、代码风格、文档语言、数据库安全、分支策略、验收标准和需要人工确认的高风险操作。

不要把所有偏好都塞进去

好的 `AGENTS.md` 是可执行的约束，不是愿望清单。每条规则都应该能回答：什么情况下触发，agent 应该做什么，什么情况下必须停下来问用户。

02Create the file

从一个最小文件开始

先在仓库根目录创建 `AGENTS.md`。如果某个子项目有完全不同的技术栈或安全规则，再在子目录补一个局部文件。

PowerShell 

          New-Item -ItemType File -Path .\AGENTS.md

03Write executable instructions

        
把规则写成可执行的块

        
规则块越具体，agent 越容易稳定执行。推荐按语言、代码、测试、安全、文档、交付拆分，而不是写一段长散文。

        

          

            
              

                规则块
                适合写什么
                避免写什么
              

            
            
              

                语言规则
                回复语言、文档语言、错误日志是否保留原文。
                要求翻译代码标识符或第三方 API 名称。
              

              

                工程规则
                代码风格、目录边界、测试命令、提交前检查。
                和 formatter、linter 冲突的个人偏好。
              

              

                安全规则
                数据库、生产环境、密钥、删除文件、外部服务调用。
                模糊的“谨慎操作”，没有说明何时要确认。
              

              

                交付规则
                最终回复格式、验证证据、已知风险、后续建议。
                要求 agent 声称完成但不跑验证。

## 语言规则

- 默认使用简体中文回复用户。
- 代码标识符、命令、配置键、日志原文和错误栈保持原文。

- 修改前先阅读相关文件和现有模式。
- 不要重构无关代码。
- 不要覆盖用户未明确要求回退的改动。

          强规则要写触发条件
          
例如“不得修改数据库”不够完整。更稳的写法是“除非用户明确提出修改表结构，否则不得创建迁移或执行 DDL”。

        

      


      

        
04Codex Rules

        
Rules 管执行权限，不管项目语义

        
Codex Rules 是审批策略：允许、阻止或要求确认某类命令能否在沙箱外运行。它解决的是“能不能执行这个外部动作”，不是“这个项目怎么写代码”。

        

          

            AGENTS.md
            
写给 agent

            
描述项目知识、协作方式、验证流程和安全边界。它让 agent 知道如何做事。

            
    
              
  • 默认回复语言
    • 
              
  • 测试命令和构建命令
    • 
              
  • 数据库变更确认规则
    • 
              
  • 代码审查输出格式
    • 
            

          

          

            Rules
            
写给运行策略

            
定义命令审批行为，尤其是沙箱外命令。它让 Codex 知道哪些命令可以放行。

            
    
              
  • 允许 `npm test` 类验证命令
    • 
              
  • 要求确认 `git push`
    • 
              
  • 阻止删除或重置类命令
    • 
              
  • 收紧网络或安装行为
    • 
            

          

        

        

          不要用 AGENTS.md 伪装权限控制
          
你可以在 `AGENTS.md` 里写“运行危险命令前必须确认”，但真正的命令审批仍由 Codex 环境、沙箱和 Rules 决定。两层都要配置清楚。

        

        

          

            Rules 设计清单
            
          

          
为 Codex Rules 设计审批策略时，逐项确认：

1. 哪些验证命令可以自动放行？
2. 哪些安装、网络或部署命令必须询问？
3. 哪些删除、重置、清库、发布命令必须阻止或强确认？
4. 是否存在团队统一规则，不允许个人覆盖？
5. 规则是否足够窄，避免把任意脚本都放行？

05Copy-ready templates

        
从模板开始，再按项目收紧

        
模板不是最终答案。复制后要替换命令、目录、测试策略和安全边界。最重要的是把“需要确认”的条件写具体。

06Debug instructions

        
规则不生效时，先查范围和冲突

        
大多数问题不是 agent “没听话”，而是规则太模糊、作用范围不对、和更高优先级指令冲突，或把执行权限规则误写进了项目说明。

        

          

            
    
              
  • 确认 `AGENTS.md` 位于仓库根目录或目标子目录。
    • 
              
  • 确认正在修改的文件落在该规则的作用范围内。
    • 
              
  • 检查是否和用户当次要求、系统规则或开发者规则冲突。
    • 
              
  • 把模糊规则改成触发条件和具体动作。
    • 
              
  • 命令审批问题去检查 Codex Rules，而不是只改 `AGENTS.md`。
    • 
            

          

          

            Case study
            

              
Context

              
团队写了“谨慎操作数据库”，但 agent 仍然生成迁移。

              
Decision

              
改成“除非用户明确要求修改表结构，否则不得创建或修改迁移脚本”。

              
Outcome

              
规则从价值判断变成可执行条件，agent 可以判断何时必须停下来确认。

07Maintenance

        
把规则当成工程资产维护

        
`AGENTS.md` 会随着项目变化过期。每次技术栈、命令、目录、数据库策略或部署方式变化，都要同步更新，否则 agent 会被旧规则带偏。

        

          

            Review cycle
            
什么时候更新

            
新增测试命令、迁移框架、部署流程、目录结构、代码规范、安全策略时，立刻更新。不要等到下次 agent 犯错后再补。

          

          

            Ownership
            
谁来维护

            
团队项目应把 `AGENTS.md` 当作代码审查的一部分。涉及权限和数据库的规则，最好由模块负责人或安全负责人确认。

          

        

        

          

            最终检查清单
            
          

          
发布 AGENTS.md 前检查：

- 是否写明项目类型和主要目录？
- 是否写明真实可运行的安装、测试、构建命令？
- 是否写明默认回复语言和文档语言？
- 是否写明禁止改动无关文件和不得回退用户改动？
- 是否写明数据库、密钥、删除、部署等高风险操作的确认规则？
- 是否区分了 AGENTS.md 和 Codex Rules？
- 是否没有过期命令、矛盾规则和空泛偏好？
