Frontend Slides 从安装到落地 PPT

面向商务团队的实战分享：用 Codex 技能把主题、风格、文案、注意点和可编辑 HTML PPT 串成一套可复用流程。

Why This Matters

对商务团队来说，PPT 不是设计活，是交付效率问题。

传统做法

  • 先写 Word，再搬到 PowerPoint。
  • 风格靠临时套模板，质量不稳定。
  • 修改一版内容，经常牵动十几页排版。

技能工作流

  • 先问清用途、受众、页数、内容状态。
  • 先看风格预览，再生成正式稿。
  • 交付一个浏览器可演示、可编辑的 HTML 文件。

Skill Basics

Skill 是把“怎么做”写进代理工作流。

它不是简单提示词，而是一份本地说明书：什么时候用、先问什么、读哪些文件、生成时必须守住哪些边界。

Mental Model SOP for AI execution

Two Skills, Two Jobs

先用 frontend-slides 定演示流程，再用 design-taste-frontend 把质感拉上去。

frontend-slides

  • 内容发现：用途、页数、内容状态、编辑需求。
  • 风格发现：先生成预览，再让用户选择。
  • 生成约束：单文件、可导航、视口安全。

design-taste-frontend

  • 避免默认模板感和紫蓝渐变套路。
  • 限制强调色、控制动效、保证移动端收敛。
  • 用工程规则表达审美判断。

Install

安装阶段不要只看“装上没”，要看技能是否能被发现。

团队落地时建议把技能来源、版本、安装方式和本地路径写进内部文档，避免每个人的环境不一致。
